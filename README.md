# گفت‌بان — فرانت‌اند

رابط فارسی و راست‌به‌چپ کنترل کیفیت مکالمات، با React، TypeScript و Vite. شامل تماس‌ها و جزئیات ارزیابی، داشبورد، گزارش‌ها و خروجی فایل، مدیریت سازمان/داخلی‌ها، مجموعه‌سؤال‌ها، بارگذاری تماس و گزارش پردازش و مصرف هوش مصنوعی.

## اجرای محلی

Node.js 24 لازم است. در نصب تازه یا پس از تغییر package-lock.json:

```powershell
npm ci
```

این دستور نسخه‌های ثبت‌شده در package-lock.json را نصب می‌کند. سپس:

```powershell
npm run dev
```

آدرس اعلام‌شده توسط Vite را باز کنید. API لوکال روی `http://127.0.0.1:8000` توسط کاربر اجرا می‌شود. مقدار اختیاری `API_PROXY_TARGET` در `.env.local` مقصد پروکسی توسعه را مشخص می‌کند؛ نمونه در `.env.example` است. متغیرهای `VITE_` عمومی‌اند و نباید حاوی رمز یا کلید سرویس باشند.

توکن ورود در مرورگر نگهداری می‌شود؛ پس از رفرش، تا پایان اعتبار همان توکن و با تأیید مجدد حساب از `/auth/me` ورود حفظ می‌شود. خروج از حساب، توکن ذخیره‌شده را پاک می‌کند. محیط نمونهٔ طراحی از برنامه حذف شده است. اجرای API به‌تنهایی Worker پردازش را فعال نمی‌کند.

## بررسی پروژه

```powershell
npm test
npm run build
npm run check
```

`npm test` تست‌های خودکار را اجرا می‌کند. `npm run build` نوع‌های TypeScript را بررسی و فایل‌های انتشار را در `dist` تولید می‌کند. `npm run check` هر دو مرحله را به‌ترتیب اجرا می‌کند و در صورت شکست متوقف می‌شود.

GitHub Actions در Push به main و Pull Request همین بررسی را پس از `npm ci` روی ویندوز و لینوکس انجام می‌دهد. این بررسی به بکند، حساب واقعی یا کلید هوش مصنوعی نیاز ندارد و سایت را منتشر نمی‌کند.

## تست و انتشار

[راهنمای پذیرش محلی](docs/LOCAL_ACCEPTANCE_FA.md) مسیرهای تست با دادهٔ واقعی و نقش‌های مختلف را مشخص می‌کند. موفقیت تست واحد و ساخت به‌معنی تأیید آزمون مرورگر یا آمادگی انتشار نیست.

`npm run preview` فقط ابزار مشاهدهٔ خروجی ساخته‌شده است، سرور انتشار نیست. پروکسی `/api` فعلی متعلق به حالت توسعه است. پیش از انتشار باید میزبانی فایل‌های dist، HTTPS و مسیریابی `/api` به بکند مشخص و آزمایش شوند.
