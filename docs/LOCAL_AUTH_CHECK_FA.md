# بررسی ورود محلی

این مرحله از قراردادهای موجود auth/login، auth/me و users/me/password استفاده می‌کند. بک‌اند تغییر نکرده است.

1. کاربر بک‌اند را روی 127.0.0.1:8000 اجرا کند؛ برای ورود و تغییر رمز Worker لازم نیست.
2. فرانت با npm run dev اجرا شود؛ اگر از قبل روشن بوده، پس از دریافت تنظیمات جدید یک بار Restart شود.
3. با ایمیل/رمز حساب موجود وارد شوید؛ رمز را در چت ارسال نکنید.
4. نام و نقش واقعی باید در حساب دیده شود. نمونهٔ طراحی از صفحهٔ ورود جداگانه قابل مشاهده است؛ حساب واقعی دادهٔ ساختگی ندارد.
5. رمز نادرست باید پیام ورود ناموفق بدهد. قطع بک‌اند باید پیام اتصال بدهد، نه صفحهٔ خالی.
6. خروج باید اطلاعات حساب و رمزها را از رابط پاک کند. Refresh ورود دوباره می‌خواهد؛ توکن فقط در حافظه است. این انتخاب اولیه است و تداوم نشست در مرحلهٔ بعد قابل بررسی است.
7. تغییر رمز فقط با قصد واقعی و ترجیحاً روی حساب آزمایشی انجام شود؛ رمز قبلی و جدید لازم است و پس از موفقیت ورود مجدد ضروری است.

پروکسی توسعه /api را به بک‌اند محلی می‌فرستد. برای مقصد متفاوت از .env.example استفاده کنید؛ فایل .env محلی commit نمی‌شود. هیچ رمز یا کلیدی نباید در متغیرهای فرانت قرار گیرد. این پروکسی جای تنظیم استقرار واقعی را نمی‌گیرد.

تست‌های tests/auth.test.mjs فقط منطق محلی با جایگزینی fetch را بررسی می‌کنند؛ اثبات اتصال واقعی، CORS یا رفتار بک‌اند نیستند. آزمون مرورگری و اتصال واقعی با کاربر باقی است.
