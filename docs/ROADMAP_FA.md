## نقاط تست با بک‌اند محلی

1. پس از ورود و پوسته: ورود نقش‌های مختلف، پایان نشست، 401/403/404 و CORS.
2. پس از تماس‌ها و داشبورد: تطبیق نتیجهٔ واقعی، NULL و صفر، پوشش، تاریخ و نسخهٔ قبلی.
3. پس از مدیریت و سؤال‌ها: محدودیت نقش، تداخل تغییرات 409، حفظ تاریخچه و انتشار.
4. پس از آپلود: ارسال مجدد امن، خطای فایل، Start، پیشرفت و حالت تماماً Skipشده. برای پردازش واقعی هماهنگی Worker لازم است.
5. پیش از انتشار: مسیرهای کامل در دسکتاپ و موبایل و مجوزهای بین دپارتمان‌ها.

تست اتصال جای تست رفتار فرانت را نمی‌گیرد. تست‌های معنادار روی نقش‌ها، تبدیل تاریخ، نشست، فیلترها و گردش کار مهم نوشته شوند؛ تغییر صرف متن/رنگ به‌تنهایی نیاز به تست جدید ندارد.

## ادامهٔ بعدی

نمونهٔ React سه صفحه ساخته شد: داشبورد، فیلتر تماس‌ها و جزئیات با انتخاب سؤال/شاهد و حالت خطا/انتظار. npm install و npm run build موفق شدند. فونت Vazirmatn محلی و دارای مجوز OFL است. مخزن محلی مستقل ساخته شد؛ مقصد GitHub هنوز مشخص نیست. قدم بعد: بررسی بصری و تعاملی دسکتاپ/موبایل، اصلاح بازگشت با حفظ فیلتر و آماده‌سازی اتصال. داده‌ها نمایشی‌اند؛ احراز هویت و API هنوز پیاده‌سازی نشده‌اند. بررسی مرورگری کامل در این مرحله انجام نشده است.

## ثبت تصمیم‌ها

آخرین پیشرفت داشبورد و تاریخ: داشبورد واقعی overview و trends متصل شد؛ نقش‌های مجاز پس از ورود به داشبورد هدایت می‌شوند. ورودی تاریخ شمسی متنی (سال/ماه/روز) در تماس‌ها و داشبورد، تبدیل مستقل از منطقهٔ زمانی مرورگر و اعتبارسنجی روز/کبیسه/ترتیب اضافه شد. انتخابگر تقویمی گرافیکی هنوز ساخته نشده است. پوشش تماس‌ها و پوشش سؤال‌ها مستقل‌اند؛ NULL صفر نیست. روند روزانه فعلاً جدول خواناست و برای بازهٔ مشخص حداکثر ۹۳ روز دریافت می‌شود. لینک کل تماس‌های محدوده فیلترها را حفظ می‌کند؛ کارت‌های کم‌نمره/شکست به فیلتر نامعادل لینک نشده‌اند. ۱۱ تست و Build موفق؛ آزمون مرورگری زنده با کاربر باقی است. بک‌اند تغییری نکرد.

آخرین پیشرفت فیلترها: انتخاب دپارتمان/کارشناس از API واقعی با دریافت همهٔ صفحات مجاز، بازهٔ نمره با کنترل ترتیب و حدود، پذیرش ارقام فارسی/عربی و نمایش مدت تماس اضافه شد. گزینه‌های کارشناس عمداً به دپارتمان جاری محدود نمی‌شوند تا جست‌وجوی تماس‌های پیش از انتقال ممکن باشد؛ API گزارش همچنان دامنهٔ دسترسی و دپارتمان تاریخی تماس را کنترل می‌کند. هشت تست و Build موفق؛ آزمون زندهٔ این فیلترها باقی است. قدم بعدی فیلتر بازهٔ تاریخ شمسی و سپس داشبورد واقعی است.

اصلاح UX ارزیابی طبق بازخورد کاربر: هر سؤال کارت مستقل، شماره براساس ترتیب، نمرهٔ درشت و وزن با یک رقم اعشار دارد. کد سؤال، برچسب «شاهد موجود»، JSON خام و بخش تکراری ساختار اصلی حذف شدند. جزئیات فقط به‌شکل خوانا نمایش داده می‌شوند؛ improvement با «پیشنهاد بهبود» ترجمه می‌شود. rubric از مجموعه‌سؤال دقیق همان Run و با item_id خوانده می‌شود تا عنوان کوتاه قدیمی همراه متن کامل معیار دیده شود. JSON خام نباید در جریان کار محصول نمایش داده شود؛ این تصمیم جای تصمیم قبلی نمایش ساختار اصلی را می‌گیرد.

تازه‌ترین وضعیت: کاربر ورود ادمین و خروج را روی بک‌اند محلی تأیید کرد. فهرست واقعی با صفحه‌بندی ۲۵تایی، داخلی/منبع/وضعیت و مرتب‌سازی، جزئیات و تاریخچه پیاده شدند؛ فیلتر تاریخ شمسی و دپارتمان/کارشناس هنوز اضافه نشده‌اند. بازگشت از جزئیات فیلتر را حفظ می‌کند. متن و شواهد واقعی‌اند؛ نمایش شاهد فقط با تطابق لفظی فعال است. پیشنهاد تغییر backend برای details در BACKEND_DETAILS_REQUEST_FA.md آمادهٔ مشورت است. هیچ تغییر بک‌اند انجام نشد. تست مرورگری زندهٔ گزارش‌ها با کاربر باقی است.
