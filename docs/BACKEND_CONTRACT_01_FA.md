# پاسخ به چت فرانت — قرارداد نهایی درخواست ۰۱

درخواست با مبنای c86770e تطبیق داده شد؛ اختلافی نیازمند گسترش دامنه وجود نداشت. پکیج آماده است؛ تا اعمال و استقرار کاربر، سرویس زنده تغییر نکرده است.

در هر عضو answers دو مسیر زیر، `details` اضافه شده است:

- GET /api/v1/reports/calls/{call_id}
- GET /api/v1/reports/calls/{call_id}/evaluation-runs/{run_id}

نوع قرارداد `dict[str, Any] | None` است. کلید در پاسخ همیشه وجود دارد. SQL NULL برابر JSON null است؛ {} بدون تغییر می‌ماند. داده تو در تو، کلید ناشناخته، false، صفر، آرایه و رشته حفظ می‌شوند. مقدار از details_json همان پاسخ و همان Run خوانده می‌شود. OpenAPI نوع object یا null با additionalProperties=true دارد؛ به علت default=None این property در required نیست، ولی serialization پاسخ کلید را حذف نمی‌کند.

مجوزهای Admin/Manager/Supervisor و دامنه دپارتمان حفظ شده‌اند؛ Analyst گزارش نمی‌گیرد. فهرست تماس‌ها، فهرست Runها و Export گسترش نیافته‌اند. اجرای جاری ناموفق answers خالی دارد؛ پاسخ قدیمی جایگزین نمی‌شود و از مسیر تاریخی مستقل قابل خواندن است.

کلیدهای نمونه صرفاً تست هستند و قرارداد rubric جدید نیستند. فقط داده QC ذخیره‌شده ارائه می‌شود؛ پاسخ خام Provider یا credential اضافه نشده است. در UI مقدار را داده غیرقابل‌اعتماد تلقی کن و به‌عنوان HTML اجرا نکن.

Migration، AI مجدد، تغییر prompt و بازنویسی داده تاریخی لازم نیست. تست زنده فرانت و Linux/MySQL بعد از اعمال و استقرار کاربر باقی است. نتیجه تست‌های کپی جداگانه در VALIDATION.md آمده است.
