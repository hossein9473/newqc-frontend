## خانواده‌های API

همهٔ مسیرها زیر /api/v1 هستند.

| صفحه | خانوادهٔ API |
|---|---|
| ورود و حساب | auth/login، auth/me، users/me/password |
| سازمان | departments، users و users/{id}/departments |
| کارشناس | support-agents و transfers و department-history |
| داخلی | support-agent-extensions با support_agent_id اجباری؛ release و reassign |
| معیارها | departments/{id}/question-sets و drafts و publish و questions |
| تماس | reports/calls و evaluation-runs |
| گزارش | reports/dashboard، agents، questions، departments |
| عملیات | reports/processing، reports/ai-costs |
| فایل خروجی | reports/export/{kind} |
| آپلود | upload-batches، options، files، start، progress، cancel |

## قراردادهای مهم

- login بدنهٔ JSON دارد. Refresh و بازیابی رمز وجود ندارند. تغییر رمز token_version را افزایش می‌دهد؛ پس از موفقیت، ورود مجدد لازم است. سیاست نگهداری token در مرحلهٔ معماری تعیین شود.
- API فهرست‌ها یک‌شکل نیست: تماس total/limit/offset دارد؛ بعضی فهرست‌های مدیریتی فقط آرایه و limit/offset دارند. تعداد کل یا جست‌وجوی سراسری از دادهٔ یک صفحه ساخته نشود.
- پاسخ بعضی مسیرهای سؤال schema کامل در OpenAPI ندارد؛ قرارداد پاسخ از کد و نمونهٔ کنترل‌شده استخراج و ثبت شود.
- زمان‌های تاریخی برخی مسیرهای مدیریتی بدون offset و طبق قرارداد DB به UTC هستند؛ با زمان offsetدار گزارش یکی فرض نشوند. تبدیل تاریخ آزمون مرزی روز تهران می‌خواهد.
- هزینهٔ نامعلوم صفر نیست؛ ارزهای متفاوت جمع نشوند. تعداد تماس، Job و Attempt نیز مخرج یکسان ندارند.
- Export سقف ۵۰۰۰ ردیف/۲۰ MiB دارد و متن کامل تماس را شامل نمی‌شود.
- آپلود فایل raw bytes است، نه multipart. upload_id هر فایل در retry ثابت بماند؛ ارسال هم‌زمان محدود باشد.
- هر Batch یک دپارتمان، انتساب داخلی و روز تهران دارد. ساعت حذف‌شده ۱۰ صبح تهران است و باید با برچسب پیش‌فرض نمایش داده شود.
- نام فنی Batch را می‌توان خودکار تولید کرد؛ کاربر عنوان فارسی می‌بیند. تاریخ و انتخاب پس از ساخت قابل ویرایش نیستند.
- مرجع پیشرفت /progress است. completed دستهٔ تماماً کوتاه به معنی ارزیابی موفق نیست.
- Cancel فقط پیش از Start است؛ حذف انتخابی فایل و توقف پس از شروع موجود نیست.
- پیشرفت با polling محدود و توقف در حالت نهایی پیگیری شود؛ ارتباط بلادرنگ فرض نشود.

## نیازهای بک‌اند؛ ثبت برای تصمیم، نه دستور تغییر فوری

| شناسه | نیاز و شاهد | اثر و اقدام پیشنهادی |
|---|---|---|
| B01 | reports.py: AnswerDetail و سازندهٔ پاسخ details_json را برنمی‌گردانند | برای نمایش جزئیات ساختاری مدل، فیلد مناسب به مدل پاسخ و mapping افزوده و دسترسی/ساختار آن تست شود؛ پیش از مرحلهٔ جزئیات تماس به کاربر تحویل شود |
| B02 | ExtensionAssign به voip_source_id نیاز دارد؛ endpoint فهرست مراکز تلفن وجود ندارد | برای فرم انتساب جدید، فهرست خواندنی و مجاز id/name مرکز تلفن لازم است؛ upload options جایگزین کامل نیست چون فقط انتساب‌های موجود را نشان می‌دهد |
| B03 | reports/calls فیلتر extension دارد ولی فیلتر source ID یا assignment ID ندارد | شمارهٔ مشترک چند PBX یا واگذاری مجدد می‌تواند نتایج را مخلوط کند؛ در نسخهٔ پایه تماس‌ها از کارشناس و فیلترهای موجود باز شوند و عنوان «تاریخچهٔ دقیق این انتساب» داده نشود؛ برای آن قابلیت API دقیق لازم است |
| B04 | داخلی‌ها فقط با support_agent_id خوانده می‌شوند | نسخهٔ پایه داخلی‌ها در صفحهٔ کارشناس باشند؛ فهرست سراسری پرحجم نیازمند endpoint صفحه‌بندی‌شده است |
| B05 | ذخیرهٔ audit_logs بدون endpoint خواندن عمومی | تاریخچهٔ اختصاصی موجود نمایش داده شود؛ Audit سراسری فعلاً خارج از محدوده |
| B06 | endpoint دریافت صوت موجود نیست | پخش صوت نیازمند مسیر مجاز و مدیریت صوت حذف‌شده است؛ قابلیت اختیاری آینده |
| B07 | refresh/reset/worker-control/settings API موجود نیست | رابط برای این قابلیت‌ها عملیات ساختگی ارائه نکند؛ نیاز محصول جداگانه بررسی شود |

هیچ‌یک از این تغییرها در بک‌اند اعمال نشده است. پیش از درخواست اجرای هر تغییر، شرح دقیق فایل و رفتار و روش بررسی آماده شود.
