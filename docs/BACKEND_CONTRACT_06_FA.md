# قرارداد خروجی تماس‌ها — درخواست ۰۶

مبنا e8abdb4؛ 2026-11-11. پکیج آماده، اعمال و Push توسط مالک؛ سرور فعلاً تغییر نمی‌کند.

GET /api/v1/reports/export/calls?voip_source_id=1&extension=105&support_agent_id=42&format=xlsx

voip_source_id اختیاری و integer مثبت است. فقط calls این پارامتر را می‌پذیرد؛ برای نوع‌های دیگر 422. صفر، منفی و غیرعدد 422. نبود فیلتر، دامنه داده قبلی را حفظ می‌کند. سایر فیلترها AND هستند؛ همان list_report_calls مرجع فیلتر، دامنه نقش، تاریخ تهران و مرتب‌سازی است.

CSV و XLSX تماس‌ها دو ستون جدید voip_source_id و voip_source_name پس از source_type دارند؛ سایر ستون‌ها حفظ شده‌اند. null در فایل خالی است. هویت VoIP از Call و هویت upload از selection ذخیره‌شده در Batch خوانده می‌شود؛ نام، نام فعلی مرکز است. برای فقط VoIP، source_type=voip اضافه کنید. Batch فاقد اطلاعات مرکز بدون فیلتر باقی می‌ماند ولی با فیلتر مرکز مطابقت ندارد. فیلتر دوره تاریخی انتساب اضافه نشده است.

Admin/Manager/Supervisor با دامنه قبلی؛ Analyst ممنوع. سقف ۵۰۰۰ ردیف و ۲۰ MiB، محافظت Formula Injection و عدم خروج transcript/details/اطلاعات اتصال حفظ شده‌اند. Export تمام ردیف‌های مطابق را می‌گیرد، نه فقط صفحه فعلی.

پس از اعمال و restart API مقصد، فرانت می‌تواند Export را هنگام انتخاب مرکز فعال کند و voip_source_id را همراه سایر فیلترهای مجاز calls ارسال کند. تا به‌روزرسانی مقصد (خصوصاً سرور که فعلاً معوق است) محدودیت فرانت را برندارید.

Ruff/format موفق؛ ۵۷ تست گزارش و Export موفق، ۸۸۲ تست کل موفق. پس از اصلاح نام fixture برای Ruff، ۲۲ تست Export دوباره موفق شد. بدون Migration، وابستگی، Worker یا AI. تست زنده فرانت و Linux/MySQL انجام نشده است.
