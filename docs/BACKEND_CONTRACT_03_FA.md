# تحویل بک‌اند به فرانت — درخواست ۰۳

تاریخ 2026-11-10؛ مبنا 3bfc66b. تغییر در کپی جداگانه آماده و تست شده است. اعمال، Commit و Push توسط مالک پروژه انجام می‌شود؛ سرور فعلاً به‌روزرسانی نمی‌شود.

## پاسخ به نیازمندی

نیاز وارد است: مسیر انتساب شناسه مرکز می‌خواهد و upload-batches/options پوشش مستقلی برای مراکز بدون انتساب و تاریخچه ندارد. endpoint مستقل افزوده شد. دامنه تغییر محدود است؛ Migration، وابستگی، تنظیم محیط، Worker یا تغییر داده لازم نیست.

## انتخابگر

GET /api/v1/voip-sources/options?limit=50&offset=0

احراز هویت Bearer JWT موجود. admin، manager و supervisor مجازند؛ analyst برابر 403، بدون احراز هویت 401. پاسخ آرایه مستقیم است، نه envelope و بدون total:

```json
[
  {"id": 1, "name": "مرکز نمونه", "is_active": true},
  {"id": 2, "name": "مرکز دوم", "is_active": false}
]
```

limit پیش‌فرض 50، حداقل 1، حداکثر 100؛ offset پیش‌فرض 0 و نامنفی. مقدار نامعتبر 422. ترتیب id صعودی؛ صفحه خالی []. اگر صفحه دقیقاً به اندازه limit بود، صفحه بعدی را هم بخوان. offset pagination snapshot ثابت در برابر تغییر همزمان داده نیست.

تمام مراکز موجود، شامل غیرفعال و بدون داخلی، قابل مشاهده‌اند. منبع تلفن به دپارتمان خاصی محدود نشده؛ مطابق قرارداد فعلی انتساب، Supervisor می‌تواند مرکز را انتخاب کند اما فقط داخلی کارشناسان دپارتمان‌های مجاز خود را مدیریت کند. گزینه بدون انتساب حذف نمی‌شود.

is_active یعنی فعال‌بودن دریافت VoIP؛ false مانع انتساب داخلی نیست. فرانت گزینه غیرفعال را صرفاً به دلیل این مقدار disable نکند. can_assign اضافه نشده است؛ مجوز کارشناس، فعال‌بودن کارشناس، وجود منبع و تداخل شماره همچنان در endpoint انتساب بررسی می‌شوند.

فقط id/name/is_active ارائه می‌شوند؛ config_key، cursor، میزبان، رمز یا تنظیمات دریافت در پاسخ نیستند.

## پاسخ داخلی‌ها

فیلد اجباری `voip_source_name: string` به ExtensionResponse اضافه شده است:

- POST /api/v1/support-agent-extensions
- GET /api/v1/support-agent-extensions?support_agent_id=...
- POST /api/v1/support-agent-extensions/{assignment_id}/release
- POST /api/v1/support-agent-extensions/{assignment_id}/reassign

بقیه فیلدها و status codeها حفظ شده‌اند. نام برای سابقه پایان‌یافته نیز برمی‌گردد. این نام **نام فعلی مرکز** است، نه snapshot نام در زمان انتساب. پس از تغییر نام مرکز، سابقه نیز نام جدید را نشان می‌دهد. id همچنان کلید هویت است.

یکتایی شماره در محدوده voip_source_id است؛ شماره یکسان در دو مرکز مجاز است. قفل‌ها و مرز انتقال valid_to قبلی = valid_from جدید و Audit حفظ شده‌اند. Supervisor خارج از دامنه 404 و Analyst برابر 403 می‌گیرد.

## زمان

قالب فعلی عمداً حفظ شد: valid_from و valid_to غیر null، رشته datetime بدون offset با معنای **UTC** هستند، مثلاً `2026-11-10T08:30:00`؛ valid_to جاری null است. در فرانت فقط برای رشته بدون offset پسوند Z را هنگام parse لحاظ کن و سپس به زمان نمایشی تبدیل کن؛ به رشته دارای offset یا Z دوباره Z اضافه نکن. ترجیح پیشنهاد برای Z در پاسخ سرور فعلاً اجرا نشد تا تغییر قالب موجود وارد این بسته نشود. زمان ذخیره‌شده یا معنای آن تغییر نکرده است.

## بررسی‌ها

تست نقش‌ها، مرکز بدون داخلی و غیرفعال، صفحه‌بندی، عدم افشای تنظیمات، نام در هر چهار عملیات و سابقه، یکتایی هر مرکز، دامنه Supervisor و OpenAPI اضافه شده‌اند. نتیجه دقیق در VALIDATION.md است. تست زنده فرانت و Linux/MySQL انجام نشده؛ پس از اعمال روی لوکال، API لوکال را restart کن و انتخابگر و چرخه انتساب را بررسی کن.
