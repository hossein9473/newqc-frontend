# پذیرش یکپارچهٔ محلی گفت‌بان

این سند برنامهٔ تست است؛ نتیجهٔ موفق ثبت‌نشده را موفق فرض نکنید. تست‌های خودکار فعلی منطق فیلتر، تاریخ، دسترسی فرانت، خطا و قرارداد درخواست‌ها را بررسی می‌کنند؛ جای تست مرورگر و مجوزهای واقعی بکند را نمی‌گیرند.

## آماده‌سازی توسط کاربر

- API را از `C:/Users/Didar/Desktop/aida/newqc/backend` با دستور فعلی اجرا کنید:
  `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload`
- فرانت را از `C:/Users/Didar/Desktop/aida/frontend` با `npm run dev` اجرا کنید.
- برای تست بارگذاری تا نتیجه، Workerها باید مطابق راهنمای بکند فعال باشند؛ اجرای API به‌تنهایی کافی نیست.
- برای مرحلهٔ اول: یک تماس تکمیل‌شده با جواب و شواهد، یک تماس نمرهٔ صفر، یک تماس ناموفق و حداقل یک مصرف هوش مصنوعی مفید است. دادهٔ نمایشی را به دادهٔ واقعی اضافه نکنید.
- برای مرحلهٔ نقش‌ها: ادمین، مدیر، سوپروایزر محدود به یک دپارتمان و آنالیست لازم‌اند. رمزها در سند/مخزن/چت ثبت نشوند.
- عملیات ساخت و تغییر فقط روی موارد آزمایشی مشخص انجام شود؛ حساب و مجموعه‌سؤال جاری بدون هماهنگی تغییر نکند.

## پیش از انتشار

- نتیجهٔ بررسی GitHub برای کامیت مورد انتشار و آزمون‌های بالا ثبت شده باشد.
- محیط مقصد، آدرس API، HTTPS و نحوهٔ سرو فایل‌های dist مشخص باشد.
- همان نسخهٔ قرارداد بکند روی مقصد اعمال شده باشد؛ قرارداد محلی به‌تنهایی آمادگی سرور را ثابت نمی‌کند.
- راهنمای اجرا، بازگشت به نسخهٔ قبلی و وضعیت Workerها با مسئول بکند هماهنگ شود.
- پس از ورود، رفرش و بازکردن مجدد صفحه تا پایان اعتبار توکن باید ورود را حفظ کند. توکن منقضی یا ردشده توسط بکند باید به ورود برگردد. قطع اتصال هنگام بررسی حساب باید امکان تلاش مجدد بدهد. خروج از حساب باید نشست ذخیره‌شده و نشست تب دیگر را پاک کند.
- در جدول‌ها، قبلی/بعدی، شمارهٔ صفحه و ورود مستقیم شماره با ارقام فارسی و انگلیسی را بررسی کنید؛ پس از دریافت داده، اسکرول باید ابتدای همان جدول باشد.
- کادر خروجی باید زمینهٔ روشن و کنترل‌های کنار عنوان داشته باشد و در عرض موبایل بدون سرریز نمایش داده شود.

هیچ استقراری با اضافه‌شدن workflow خودکار انجام نمی‌شود.
