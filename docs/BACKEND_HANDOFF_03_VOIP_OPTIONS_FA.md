# درخواست ۰۳ — انتخاب مرکز تلفن در مدیریت داخلی‌های گفت‌بان

این فایل درخواست توسعه برای چت بک‌اند است؛ کد بک‌اند در چت فرانت فقط خوانده شده و تغییر نکرده است.

## مسئله و هدف
API انتساب داخلی در `backend/app/api/routes/support_agent_extensions.py` فیلد `voip_source_id` می‌خواهد. در مسیرهای فعلی API فهرست مراکز تلفن پیدا نشد. کاربر باید مرکز تلفن را با نام انتخاب کند، نه شناسهٔ دیتابیس. همچنین تاریخچهٔ داخلی‌ها فقط شناسهٔ مرکز را برمی‌گرداند.
`/upload-batches/options` جایگزین کافی نیست: به انتساب‌های جاری و کارشناسان فعال یک دپارتمان محدود است؛ مرکز بدون انتساب یا انتساب تاریخی را پوشش نمی‌دهد.

## تغییر پیشنهادی
۱. افزودن GET `/api/v1/voip-sources/options` با پاسخ صفحه‌بندی‌شدهٔ سازگار با فهرست‌های فعلی (آرایه، limit پیش‌فرض ۵۰ و حداکثر ۱۰۰، offset و ترتیب پایدار id). هر ردیف فقط `id`, `name`, `is_active` و در صورت نیاز `can_assign` داشته باشد. این مسیر صرفاً برای انتخاب مرکز موجود است؛ ساخت/ویرایش تنظیمات VoIP در این درخواست نیست.
۲. دسترسی برای admin/manager/supervisor مطابق امکان انتساب داخلی در قرارداد موجود؛ analyst مجاز نیست. اگر سیاست دامنهٔ مراکز تلفن متفاوت است، آن را صریح تعریف و با مسیر انتساب هماهنگ کنید. انتخابگر باید مراکز بدون انتساب قبلی را نیز برگرداند.
۳. افزودن `voip_source_name` به ExtensionResponse تمام مسیرهای فهرست، انتساب، آزادسازی و انتقال داخلی. فیلدهای قبلی بدون حذف یا تغییر باقی بمانند و تاریخچهٔ انتساب پایان‌یافته نیز نام مرکز را داشته باشد.
۴. معنای `is_active` را روشن کنید: آیا فقط فعال‌بودن همگام‌سازی است یا مانع انتساب نیز هست؟ API فعلی فقط وجود مرکز را بررسی می‌کند. بدون تصمیم صریح این رفتار تغییر نکند؛ اگر انتساب باید محدود شود، فیلد can_assign و اعتبارسنجی سمت سرور با هم هماهنگ باشند.

## الزامات
- config_key، میزبان، اطلاعات اتصال، رمزها، وضعیت داخلی همگام‌سازی و سایر تنظیمات در پاسخ انتخابگر نیایند.
- یکتایی داخلی همچنان در محدودهٔ مرکز تلفن است؛ شمارهٔ یکسان در دو مرکز مختلف مجاز است.
- عملیات release/reassign باید قرارداد تاریخی و قفل‌های فعلی را حفظ کنند.
- ساختار خروجی timestamps و UTC بودن زمان‌های بدون offset در قرارداد مستند شود (ترجیحاً خروجی دارای Z برای رفع ابهام، بدون تغییر معنای زمان).

## آزمون پذیرش
نقش‌های مجاز/غیرمجاز، صفحه‌بندی پایدار، مرکز بدون داخلی، نام مرکز در سابقهٔ پایان‌یافته، عدم افشای تنظیمات اتصال، رفتار مرکز غیرفعال و سازگاری assign/list/release/reassign بررسی شوند. تست‌های موجود نیز اجرا شوند.

## خروجی مورد درخواست از چت بک‌اند
لطفاً پکیج تغییرات، تست‌ها، راهنمای اعمال و قرارداد نهایی API را بده؛ فایل‌ها و تغییرات احتمالی migration را مشخص کن. اعمال و commit/push بک‌اند توسط مالک پروژه انجام می‌شود. پس از دریافت قرارداد نهایی، فرانت انتخابگر مرکز، ثبت داخلی، آزادسازی، انتقال و تاریخچه را کامل می‌کند.
